# 代际与生命

> 蓝图第 3 章的落地记录。原则一条不差地照抄：孩子只能被生出来、未成年代码级隔离、
> 成年即不老、死亡真实存在、财产沿家庭图继承。
> 代码入口：`sim/src/lifecycle.mjs`（阶段与遗传）、`sim/src/world.mjs`（动作与结算）。

---

## 一、时间线

一天 = 12000 tick = 20 分钟真实时间。所有原住民出生时 `ageDays = 0`，
每天（游戏日）跨过的那一刻 `tickLifecycle()` 结算（`world.step()` 内，纯 tick 函数，不掷骰子）。

**一岁 = 12 游戏日**（与成年阈值对齐：满一岁即成年，半岁为少年）。

| 年龄（游戏日） | 阶段 | 解锁 |
|---|---|---|
| 0 – 5 | child（童年） | 走、说、听；其他一切都不行 |
| 6 – 11 | teen（少年） | 同上（可以开始观察世界了） |
| ≥ 12 | adult（成年） | 婚配、独立财产、自由迁徙、可被外部 AI 接管 |
| 之后 | 不再有新阶段 | 成年即不老（蓝图 3.3） |

注册空降进来的"旅行者"直接成年（`origin: "traveler"`）——他们是客人，不是原住民。

## 一之二、生日与手动成长（可选模式）

每个角色带 `bornDay`（**创建那天的游戏日 = 生日**）和 `aging` 模式：

| 模式 | 谁在用 | 行为 |
|---|---|---|
| `auto`（默认） | 原住民、世界里出生的孩子 | 每个游戏日自动 +1 天，世界替他长大 |
| `manual`（可选） | 注册空降的旅行者 | 平时一岁不长，由用户决定；生日保底 |

手动成长规则（`aging: "manual"`）：

- **可由小长大，不能变小**：`mutate age` 拒绝任何调小（`age_cannot_shrink`）；`growUp` 永远只加。
- **用户决定长大**：`growUp`（+1 岁 = +12 游戏日），两次决定**至少隔一个游戏日**（`grow_cooldown`）。
- **最晚一年一次**：生日那天（创建日每满 12 游戏日）自动 +1 岁——用户从不管，角色也不会永远停在原地。
- 接口：角色本人 `POST /api/agents/<token>/growup`；管理员 `POST /api/admin/growup`；
  模式切换 `mutate setAging`（管理员）。

事件：`aged_up`（via = manual / birthday，daily 不发避免噪音）、`grown_up`、`came_of_age`。

## 二、未成年硬隔离（蓝图 3.2，代码级）

引擎在**三个层面**拒绝，不靠模型自律：

1. **注册入口**（`server.mjs`）：`/api/agents/register` 只挑成年且未被接管的村民；
   全被占满时空降一个**成年**旅行者，绝不会把孩子递给人类。
2. **变更通道**（`world.mutate external`）：对未成年 `on: true` 直接拒绝，`reason: "minor_isolated"`。
   旧存档里被接管的孩子读档后也不会被放开（`loadSave` 之后状态不变）。
3. **动作层**（`world.applyAction`）：未成年做 `quote / accept / publish / placeBid /
   buildHouse / propose` 全部 `reason: "minor"`。走、说、听不受限——孩子是孩子，不是囚犯。

死亡同理：**未成年人 hp 归零只会倒下，永远不真死**（mortal 世界也一样）。

## 三、婚配与生育

- `propose {targetId}`：成年、未婚、面对面、≤3 格。和报价一样是"要约"，60 秒有效，
  一人同时只能挂一个。求婚不等于结婚——对方不答就过期。
- `answerProposal {proposalId, accept}`：只能答发给自己的。答应后家庭图双向登记，
  旁观者收到 `saw_wedding`。
- `giveBirth {name?}`：已婚、配偶在 3 格内、3 游戏日冷却。孩子 0 岁出生，
  天赋（父母均值 ±0.15 变异）、性格（均值 ±2）、底色（二选一）由父母混合，
  混合顺序固定、只消耗 `world.rng`——同一本流水重跑，生出来的是同一个孩子。

## 四、死亡与继承

- `MORTAL=1` 启动时成年人才会真死（默认关：墓地/遗嘱配套没齐之前不清理村庄）。
- 死亡不可逆：`state = "dead"`，不再移动、不被感知、不能动作、不能被接管、不进新存档循环。
- 继承顺序：配偶 → 最年长的成年子女 → 任意子女。钱、货、房子原样转移，发 `inherited` 事件。
  没有继承人就是绝户：财产随人清空，发 `estate_lost`。
- 引擎仍然不判定欠债（蓝图 5.2）：`debtors` 是村民自己记的小本本，不在继承范围里。

## 五、接口变化

- `pub()` 新增 `stage / ageDays / family{parents, spouseId, children} / origin`，
  `talent` 照旧不外露。
- 存档版本 v3：`ageDays / origin / family / nextBirthTick` 入档；v1/v2 老档可读，
  没有年龄的实体一律按成年处理（不替历史编故事）。
- 管理员：`POST /api/admin/age {villagerId, ageDays}`（演示/测试用，不影响随机流）。
- 本地 NPC 大脑（`brain.mjs`）：未成年走 `childUpdate()`——跟家人、
  在家附近玩、说孩子的话；不交易、不开拍卖、不贴告示。

### 回放的三个坑（已修）

1. **回放顺序**：与开局快照同 tick 的动作（服务刚起就来的注册）被"先 step 再喂"整整推后一步，
   表现为偶发 hash 对不上（少耗一体力）。改为"动作先落、再走下一步"。
2. **未初始化字段**：`spawn()` 里 `nextBirthTick` 没初始化，"没序列化过的实体"和
   "序列化往返过的实体"指纹不同（null vs 0），注册空降必分叉。教训：**实体字段必须
   在 spawn 里全部初始化，序列化往返不能改变世界指纹。**
3. **`Number(null) === 0`**：序列化写出 `lastGrowDay: null`，读档处
   `Number.isFinite(Number(x))` 把 null 当 0 收下——又是"往返改变指纹"。凡序列化可能出
   null 的字段，读档必须先排除 null。
