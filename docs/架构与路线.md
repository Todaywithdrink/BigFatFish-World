# 架构与路线：从"魔改星露谷"到"独立游戏 + 服务器"

> **状态说明：已归档历史文档（Historical Reference）**  
> 本文档记录了项目早期基于《星露谷物语 1.6》+ SMAPI 进行技术验证时的探索记录。  
> **当前主线已完全独立为自研纯逻辑模拟内核（`sim/`）**。本文仅保留作为操作手感、美术风格参考及版权隔离红线的历史档案。

## 1. 目录即职责 (历史原型时期)

    E:\Data\DeepSeek\Game\
    ├─ runtime\stardew\      干净副本 + SMAPI 4.5.2 —— 我们的"引擎基线"，所有改动只发生在这里
    ├─ mods\AiVillagers\     C# 模组：游戏逻辑（对话、将来的日程/经济/关系）
    ├─ bridge\               外部大脑：提示词、记忆、模型调用
    ├─ tools\smapi\          SMAPI 安装包（重建副本时用）
    ├─ start.bat             一键起桥接 + 起游戏
    └─ docs\

原始安装 C:\Program Files (x86)\Steam\steamapps\common\Stardew Valley 已经恢复成未装 SMAPI 的干净状态，
以后任何改动都不碰它。

## 2. 运行链路

    玩家客户端 ── Steam/直连 ──► 主机（跑 runtime\stardew）
                                    └─ Mods\AiVillagers ──HTTP──► 本机或内网 bridge ──HTTPS──► 模型

模组是"瘦客户端"：它只负责把游戏状态抛出去、把台词接回来。
提示词、记忆、换模型、限流、计费，全在 bridge 里——换模型不用重编译模组，也不用让玩家更新客户端。

## 3. 多人：现在能做什么，不能做什么

星露谷 1.6 的原生多人是"主机带着存档跑，最多 4 人（房主 + 3 个农夫）"，
走 Steam 邀请或 IP 直连（UDP 24642）。没有官方无头专用服务器，游戏逻辑和 MonoGame 渲染是耦合的。

所以"放到服务器上给多人跑"只有三条路，成本差一个数量级：

| 方案 | 做法 | 代价 | 适合 |
|---|---|---|---|
| A. 带显示的主机 | Windows 云主机（带虚拟显示器驱动）跑房主进程，自动读档、开机自启、断线重连 | 每月一台带 GPU 或虚拟显示的 Windows 机器；一次只能一局 4 人 | 现在就该走的路 |
| B. 串流 | 一台机器跑游戏，玩家通过串流看画面 | 延迟敏感；AI 世界的观众本来就在看画面，反而合适 | 直播式体验 |
| C. 真服务端 | 把世界模拟从客户端剥离，自研服务端 + 客户端渲染 | 等于重写，1.6 的代码没为这个设计过 | 中期以后再谈 |

结论：短期不要幻想"一个进程挂几百人"。先做 A：一台主机 = 一个村子 = 4 个真人 + 任意多 AI 村民。
想扩就是多开主机，每个村子自带一份 AI 预算。

## 4. 存档隔离（现在的一个坑）

两个安装共用 %APPDATA%\StardewValley（存档、选项、日志都在这里），因为游戏用
Environment.GetFolderPath(ApplicationData) 硬解析路径，改环境变量没用（已实测确认）。

现在的影响：开发副本会看到你自己的存档，读档存盘会覆盖同名存档。

短期对策：开发时用独立农场名（如 DevWorld），不要覆盖既有存档。
正式做服务器时必须用独立的 Windows 用户跑主机，这一步留到部署阶段。

## 5. 版权红线（别踩）

原版的美术、音乐、剧情文本、以及 Stardew Valley.dll 本身都属于 ConcernedApe，不能随你的游戏一起分发。

- 自己做开发副本、自己玩：没问题。
- 把改过的整包发给别人 / 挂到服务器让陌生人玩：等于再分发原版资源，需要授权。
- 想真正"独立游戏"化，只有两条：拿到授权，或者逐步换掉美术与内容（代码逻辑可以留着自己的）。

现阶段建议：只分发 Mod + 桥接服务，玩家自备正版；服务器运营则走"玩家连你的主机，主机也持正版"的模式。

## 6. 下一步优先级

1. 把对话路径实测通过（现在只验证了加载成功，没在游戏里点过）。
2. 让村民知道旁边站着谁、日程、节日、送礼 —— 触发点从 1 个扩到 5 个。
3. 记忆从"6 轮对话"扩到关系账本（对每个人的好感、欠人情、矛盾）。
4. 一台云主机跑通"自动开局 + 4 人连入"。
