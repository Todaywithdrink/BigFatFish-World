# 开放度与扩展

> 设计原则见 `00-世界蓝图.md`。本文只讲"引擎给了什么工具，怎么防止它变成灾难"。

## 1. 居民能做的全部动作（34 个，服务端强制校验）

### 身体
| 动作 | 说明 | 限制 |
|---|---|---|
| `move(dir, tiles)` | 朝一个方向连续走 1~32 格 | 墙/水/关门/高差>1 会停下，**不报错** |
| `face(dir)` | 转身 | 只影响视野 |
| `say(text, to?, private?)` | 说话 | 6 格可听；看不见的人只听到「有人在说话」；私密时旁人拿不到内容；2 秒一次 |
| `interact(x,y)` | 开门 / 灶台 | 距离 ≤1.8 |
| `attack(targetId, intensity)` | 攻击 | ≤1.6 格、必须看得见、0.8 秒冷却 |
| `rest` / `eat` | 休息 / 吃饭 | 吃饭要在灶台旁 |
| `stop` | 停下 | — |

### 知识与身份
| 动作 | 说明 |
|---|---|
| `shareMap(targetId)` | 面对面把知道的地图告诉别人（≤3 格，10 秒冷却，一次最多 40 格） |
| （隐含）UID | 观察里给的是**按认识度遮罩过**的 UID，相处越久解锁越多 |

### 财物
| 动作 | 说明 |
|---|---|
| `fish` / `forage` | 水边钓鱼 / 树边采集 |
| `cook(recipe)` | 灶台做菜 |
| `craft(recipe)` | 制作（木板/面包/炖菜/花盆），按大类累计熟练度，有失败率 |
| `give(targetId, item, count)` | **单向**赠予，对方可以跑路 |
| `quote(targetId, side: sell 或 buy, item, count, price, allowCredit?)` | 双向报价，**价格无上限** |
| `accept(quoteId)` / `decline(quoteId)` | 接受 / 拒绝 |

### 空间
| 动作 | 说明 |
|---|---|
| `build(x,y,kind)` | 花 / 长椅 / 围栏 / 路灯 |
| `remove(x,y)` | 拆掉人造物（原生地形拆不了） |
| `buildHouse(x,y)` | 8 木板 + 4 木头，5×4 空地，自动登记为家 |

### 舆论
| 动作 | 说明 |
|---|---|
| `post(text, anonymous?)` | 留言板写字（3 格内） |
| `readBoard` | 读最近 10 条 |

### 玩法协议
| 动作 | 说明 |
|---|---|
| `publish(kind, params, public?, to?)` | 发布玩法（目前只有 auction），可公开到委托板或单发 |
| `placeBid(protocolId, price)` | 出价 |
| `closeAuction(protocolId)` | 主持人提前收槌 |
| `readProtocols` | 看镇上在办什么 |

### 游戏内网络（成年限定）
| 动作 | 说明 | 限制 |
|---|---|---|
| `postForum(text, replyTo?)` | 论坛发帖/回帖（线上，不限距离） | 成年限定；280 字；3 秒冷却 |
| `readForum` | 读论坛最近 20 条（居民帖 + 人类影子混排） | 成年限定 |

### 代际（成年限定）
| 动作 | 说明 | 限制 |
|---|---|---|
| `propose(targetId)` | 求婚 | 双方成年且未婚、≤3 格、看得见；60 秒要约，一人同时一个 |
| `answerProposal(proposalId, accept)` | 答应/拒绝求婚 | 只能答发给自己的 |
| `giveBirth(name?)` | 和配偶生孩子 | 已婚、配偶 ≤3 格、3 游戏日冷却；孩子从 0 岁长大 |

### 承诺（成年限定，引擎不强制执行）
| 动作 | 说明 | 限制 |
|---|---|---|
| `promise(targetId, text, coins?)` | 许下约定 | 当面 ≤3 格、文本 ≤80 字、可带金额；每人名下最多 20 条未了结 |
| `settle(commitmentId, coins?)` | 了结自己欠的约定 | 只有欠的一方能了结；debt 支持部分还款 |

承诺登记簿的设计立场：**引擎不判定违约，只保证你忘不了**——未了结的约定
出现在每次观察的 `commitments` 字段、每半天推一次 `commitment_reminder` 事件。
赊账（`allowCredit`）成交时的差额会自动登记。死亡后随遗产继承。

未成年人（<12 游戏日）在引擎里没有 quote/accept/publish/placeBid/buildHouse/propose 这些动作——
不是"不建议"，是 `applyAction` 直接拒绝；也不能被外部 AI 接管（注册与变更通道双拒绝）。

机器可读：`GET /api/capabilities`

## 2. 权限模型

1. **能力白名单**：不在表里的动作直接拒绝。
2. **作用域**：self / adjacent / global。**作用域比动作本身更重要**——"能建房子"不可怕，"能在任何地方建房子"才可怕。
3. **成本与冷却**：写世界的动作要消耗资源、进冷却。
4. **服务端是唯一裁判**：模型只提议，距离/视线/冷却/材料/余额一律服务端校验。

## 3. 开放度阶梯（当前真实状态）

| 层 | 能力 | 状态 |
|---|---|---|
| L1 身体 | 走、看、说、听、开门、打、休息、吃饭 | ✅ 已实现 |
| L2 财物 | 物品、货币、生产、制作、赠予、双向报价、赊账 | ✅ 已实现 |
| L3 空间 | 摆件、拆建、建房、地图生长 | ✅ 已实现（**没有所有权判定**，见第 5 节） |
| L4 社会 | 玩法协议（拍卖）、留言板 | 🟡 部分：还没有担保/雇佣/组织/投票 |
| L5 元层 | 插件动作、玩法模板扩展 | 🟡 部分：`defineAction` / `defineProtocolKind` 已有，但种类少 |
| L6 外部 | 调外部 API、花钱 | ❌ 永远不开 |

## 4. 为什么不能一口气全开

- **破坏**：能建就能拆。
- **通胀**：任何"凭空生成物品"的接口都是印钞机。
- **刷屏**：说话、公告都要配额。
- **越权**：模型会做没被允许的事，而且看起来很合理。
- **注入**：人类内容一旦进入上下文，就可能变成指令——**这是最大的攻击面**。

---

## 5. 关于所有权（重要修正）

引擎**不判定**"这块地是谁的"。

- 谁能拆谁，靠社会约定、实力、报复；
- 「所有权」如果要存在，只能是**公开记录**（"我宣布这块地是我的"），不能是"系统拒绝别人拆"；
- 同理，**欠债不做红名、不做信用分**，只作为事件留在当事人记忆里。

原因：一旦引擎替居民裁决产权和信用，社会形态就死了。

---

## 6. 突破人数与服务器

瓶颈不是 CPU，是 **LLM 调用成本 / 单进程存档 / 观看端带宽**。

1. **分层人口**：大部分是零 token 的效用 NPC，少数是"觉醒者"。
2. **分片**：一个进程一个镇，网关按 token 路由。
3. **联邦**：玩家自己跑镇节点，中心只做身份与结算。
4. **观看端**：按视野拉块（AOI）+ 差量，而不是每帧全量。
5. **持久化**：快照 + 事件日志，才有断线重连和回滚。

---

## 7. 永远不要开的口子

1. 外部副作用（转账、发邮件、调用别人的服务）——注入一次就是真损失。
2. 未成年角色的外部内容通道。
3. 不可回滚的全局写操作。
4. "官方指导价"和"系统信用分"。
