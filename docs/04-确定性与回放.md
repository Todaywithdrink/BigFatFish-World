# 确定性与回放（黑匣子）

> 2026-11-04。这一篇解释两件事：为什么内核里不能有 `Math.random`，以及出了事怎么把一段时间原样重跑一遍。

## 一、为什么先做这件事

`world.mjs` 顶上一直写着「确定性 tick」，但实际上 `Math.random` 散在内核、NPC 大脑、地形生成三处，`Date.now()` 还会被拿去当种子。后果不是"不够优雅"，而是三件事同时做不了：

1. **复现线上 bug**：同一份存档跑两遍长出两个世界，日志对不上代码。
2. **对比实验**：想看"如果老鲤那天没把鱼卖给团子会怎样"，必须先能把其他条件冻住。
3. **回放审计**：文档里"按 tick 回放 / 撤销"这条欠账，前提就是 tick 可复现。

对一个主打"白纸演化"的世界来说，第 2 条是核心能力——不是看它长成什么样，而是能对着同一个起点比较不同经历。

## 二、随机源：`sim/src/rng.mjs`

只有一个 32 位状态，mulberry32，够快够小，JSON 里存一个整数就能带走。

```js
const world = new World(map, { seed: 20261104 });
world.rng.next();     // [0,1)
world.rng.int(6);     // [0,6)
world.rng.pick(list);
world.chance(0.25);   // 带边界保护：NaN / 负数都当 false
```

规则很简单：**内核里出现 `Math.random()` 就是 bug**。`tools/determinism.mjs` 的第 4 项会读源码检查，`world.mjs` / `brain.mjs` 里有裸随机就报红。

已经改掉的三处：

| 位置 | 原来 | 现在 |
|---|---|---|
| `world.uniqueUid` / 天赋 / 钓鱼 / 制作 / 裁缝颜色 | `Math.random()` | `this.rng.*` |
| `agents/brain.mjs` 全部决策 | `Math.random()` | `world.chance()` / `world.rng` |
| `terrain.mjs` 河流断点 | `Math.random()` | 绝对坐标哈希 `hash2(x0+x, y0+y)` |

地形那处特意没用全局 rng：河流断在哪里必须只由"这块地的坐标"决定，否则同一块地按不同顺序生成会长得不一样，存档里的地形和重新长出来的就对不上。

**异步的地方要提前取值。** `brain.maybeSpeak` 里的兜底台词和"是否悄悄话"原来在 `await` 之后才掷骰子；几个会话同时在飞时，`await` 的恢复顺序本身不稳定，同一存档就会分出两条世界线。现在这两个随机值在 `await` 之前取好。

## 三、存档：`sim/src/persist.mjs`

序列化和反序列化从 `server.mjs` 搬到独立模块，因为回放工具也要能把"某个时刻的世界"原样装回去。存档多带两个字段：

- `seed`：世界种子
- `rngState`：随机流当前状态

**读档时随机流必须在 `spawn` 之后恢复。** 因为 `spawn` 本身要消耗随机数（uid、天赋），先恢复会被这些消耗推着往前走。

## 四、黑匣子：动作流水

`world.startJournal()` 之后，两个入口都会记录：

- `applyAction(v, action)` —— 所有动作，包括 NPC 大脑和外部 AI 的
- `world.mutate(m)` —— 不经过动作但要改世界的事：改名、被接管、管理员发放、传送、地图生长、中途新生

记的是**输入**，不是结果。结果由内核自己算，只要种子和输入一致，结果必然一致。所以流水很小，而且可以直接改一条重跑——这就是"反事实实验"的做法。

`mutate` 支持的变更：`rename` / `external` / `grant` / `teleport` / `home` / `appearance` / `spawn` / `grow`。

导出：

```bash
curl -H "authorization: Bearer $(cat data/admin.key)" \
     http://127.0.0.1:8090/api/admin/journal > /tmp/journal.json
```

返回 `{seed, startedAt, tick, overflow, count, hash, start, endState, actions}`，约 38 KB。

## 五、回放

```bash
node tools/replay.mjs /tmp/journal.json          # 重跑并比对
node tools/replay.mjs /tmp/journal.json --verbose # 连被拒的动作一起打
```

输出：

```
起点  tick 0  hash de8a8fd02aa84cb6  2 条鱼
终点  tick 49  hash e0e6a79b23adc6c7
动作  8 条
重跑完成  0.01s  (49 tick/s)
动作  6 条生效 / 2 条被拒（被拒是正常的：冷却、距离、库存都在变）
结果  hash e0e6a79b23adc6c7
✓ 完全一致：这段历史是确定的，可以放心拿它做对比实验。
```

被拒是正常的：回放看到的是"当时递交了什么"，不是"当时成功了什么"。冷却中、距离太远、库存不够，都会被拒，而这本身也是可复现的。

对不上时它会指出**第一个分叉的字段**并按概率列出原因（墙钟、异步回调、流水截断）。被拒的理由不想看就加 `--verbose`。

## 六、过程中真踩到的三个坑

这三个都是写回放时被"逐字段比对"直接抓出来的，不是猜的：

1. **`serializeWorld` 返回的是活引用。**
   `clock`、`needs`、`skills`、`inventory` 在 world 里是同一个对象，原样放进返回值后，这份"快照"会跟着世界一起变。存盘时立刻 `JSON.stringify` 看不出来，但黑匣子的开局快照留在内存里，几秒后就变成了"现在"——回放因此整整多跑 49 个 tick。
   **修法**：`serializeWorld` 出口统一深拷贝。

2. **`external` 没进存档。**
   谁正被人类 AI 开着，读档回来全变成 `false`。这在以前只影响"村民归还"，但它是世界状态的一部分。
   **修法**：序列化带上、反序列化恢复。

3. **`applyMutation` 先查实体，再分派。**
   "地图生长"和"中途新生"根本没有实体可查，于是永远返回 `no_entity`——表现是**村民用完后再注册直接 400**。这个 bug 在线上是致命的（新玩家进不来），而且只在"没有空位"时才触发，手测很容易漏。
   **修法**：`grow` / `spawn` 在查实体之前处理；并加了一条冒烟用例专门打这个路径。

## 七、限制（写清楚，免得被当成万能）

- **流水只在内存里**，进程重启就没了，上限 20 万条（`JOURNAL_LIMIT`）。要长期留存，自己把导出结果落盘。
- **绕开 `applyAction` / `mutate` 直接改世界的东西，回放都会对不上。** 插件、管理脚本、将来任何新入口，都必须走这两条路之一。这不是约束，是审计的前提。
- **`BRAINS=1` 时本地 NPC 会调 LLM**，LLM 的回复本身就不可复现；但它的**动作**被记进流水了，所以回放照样对得上——这可能是这套机制最实用的地方。
- 回放速度约 50 tick/s（含每 tick 的完整 `JSON.stringify` 比对开销）。跑一天（12000 tick）大概几十秒。
